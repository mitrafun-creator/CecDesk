# Шаблон карточки задачи / баг-репорта

Скопируйте блок ниже в новую секцию в [`pm/TASKS.md`](TASKS.md) или в отдельный файл `pm/cards/TASK-NNN.md` для крупных фич.

```markdown
## TASK-NNN: <Короткое понятное название>
- **Тип:** Feature | Bug | Chore | Release
- **Приоритет:** P0 (блокер) | P1 (важно) | P2 (обычный) | P3 (позже)
- **Компонент:** backend | ui | firmware | steamos | docs | release
- **Статус:** INBOX | SPEC | IN_DEV | IN_QA | READY | DONE

### 1. Запрос Бизнеса / Поддержки
Что попросил пользователь или какую проблему нашли (симптом, шаги воспроизведения, версия).

### 2. Анализ и критерии приёмки [Аналитик]
- [ ] Критерий 1 (измеримый результат)
- [ ] Критерий 2 (совместимость со старыми конфигами / ОС / устройствами)

### 3. Архитектура и тест-план [Тимлид + QA до кода]
- Затрагиваемые модули: `...`
- Риски / краевые случаи: `...`
- Чем проверяем: unit-тесты, clippy, сборка, ручной сценарий.

### 4. Итоги проверки [QA + Релиз-инженер]
- Тесты: `PASS / FAIL` (точными результатами после финальной правки)
- Запись в `CHANGELOG.md`: добавлена в `[Unreleased]` / версию `X.Y.Z`
```
